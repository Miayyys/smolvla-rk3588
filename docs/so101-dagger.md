# SO101 DAgger：在策略访问的状态上补充专家纠偏标签

日期：2026-10-19。分支：`experiment/so101-goal-conditioned`。本地RTX 4060 Laptop（GPUServer已停机）。

目的：基线A欠拟合且闭环误差累积；实验B（真值目标）改善了接近但没有提高完成率（[设计文档第11节](so101-goal-conditioned-design.md)）。示教只含专家自己的状态，策略偏离后没有恢复示范。本轮在A（原SmolVLA结构，第10000步）实际访问的状态上请脚本专家给出动作块，加入训练，检验能否提高闭环完成率。

## 1. 评测口径

渲染存在微小非确定性，同一种子的闭环结果不可逐次复现（设计文档11.3）。本轮起统一用全部100个验证种子、每个条件评测2次；每块执行10步，10步Euler，上限900步，成功即停。

|---|---|---|---|

## 2. 失败分析（`scripts/so101_grasp_drop_analysis.py`）

“抓取丢失”= `is_grasped`连续≥3步后变0。按此刻状态分类：方块离目标<3cm为放置松开；夹爪命令>15为策略张开；否则为夹紧命令下滑落。专家参照（v2训练帧lift/carry阶段）：夹爪命令0.24，状态中位数12.7（5–95%为10.9–14.0）。

| | A第10000步（100种子） | B第5000步真值目标（30种子） |
|---|---|---|
| 完成/抓住 | 6 / 27 | 3 / 14 |
| 从未进20mm且未抓住 | 38 | 4 |
| 进20mm但未抓住 | 35 | 约14 |
| 抓取丢失事件 | 26：放置松开12、夹紧下滑落11、策略张开3 | 15：放置松开10、滑落3、策略张开2 |
| 抓住期间夹爪状态中位数 | 12.4 | 12.5 |

- A：73%的回合从未抓住，主要问题仍是接近与抓取；抓住后11次在搬运途中滑落（方块高约8cm、离目标约7cm），此时夹爪命令与状态都与专家相同，原因未拆分（可能是抬起/搬运时的姿态或速度）。
- B：放置松开10次中，5次在方块高6.5–10.6cm时就张开（门控处于carry/lower，目标开口为闭合），方块落下后滑出10–12cm；另5次在低处（1.0–1.5cm）离目标0.6–2.2cm松开，但张爪/撤离时把方块带到2.5–5.3cm，仅有的完成也是2.40–2.49cm（阈值2.5cm）。专家参照：开始松开时方块高度中位数1.49cm，最终离目标中位数0.47cm（90%：0.92cm）。
- 成功判据（Nexus `pick_and_place.py`）：方块水平离目标≤`goal_thresh`=0.025m、高度<初始+1cm、静止且未被抓住。

## 3. 标签方式的选择

### 3.1 被否定的做法（实测）

1. **沿策略轨迹记录每步专家标签**（与v2数据同样的组块方式）：A驾驶时，标签与当前关节之差中位数13–36°、95%分位27–71°（v2无噪声0–0.45°/1.5–3.5°，3°噪声档0.85–1.1°/5.9–7.1°）。原因：专家的参考点按自身计划推进，不跟随机器人，标签变成“计划此刻的位置”，取决于专家内部进度而不是可观测状态。
2. **超过阈值时把专家拉回机器人**（3cm/8°）：专家自己驾驶时也会触发（无噪声种子0触发1次、标签改变7.1°；3°噪声档每段上百次）。专家自身的参考点–TCP距离无噪声时99%分位9.8cm、最大19cm，标签–关节差99%分位22.7°、最大30.7°（接触阻挡时），阈值无法区分。
3. **每步都拉回**：专家自驾20个无噪声种子完成16/20（原18/20），完成步数中位数577（原251），慢2.3倍；原因是阶段判定里“接触阻挡时停滞即视为到达”基本失效，只能等超时。节奏与v2标签不一致。

### 3.2 采用：专家接管（`qvla/evaluation/collect_so101_dagger.py`）

- `rollout`（GPU）：策略按评测方式闭环驾驶（每块执行10步，流噪声种子500000起，与评测900000区分）；脚本专家并行运行只用于跟踪阶段。每5步存一个样本：两路JPEG（质量90，同v2）、关节状态、MuJoCo完整积分状态（`mjSTATE_INTEGRATION`）、跟踪专家在本步`act()`之前的内部状态、是否抓住。成功后再保留30步。
- `label`（CPU 8进程）：在另一个无相机环境中按同种子重置（场景布局）后恢复该积分状态，由脚本专家**接管**并无噪声控制50步，其50个命令即该样本的动作块（提前结束则填充掩码）。即“专家从这个状态自己会怎么做”，与v2标签同一约定。
- 接管阶段规则：抓住时，若跟踪专家处于close/lift/open或已有放置姿态的carry/lower则沿用，否则从此处开始lift；未抓住时，跟踪专家处于open/retreat/hold则沿用；方块已在圆盘上则从此处撤离；处于descend/close且TCP在接近线段上（侧偏≤2cm、后退≤pregrasp后退量+2cm）则沿用；其余从pregrasp重新规划（按当前方块位姿重新选抓取姿态）。沿用时，若跟踪专家的参考点离TCP≤3cm且上一命令离关节≤8°，保留其参考点与上一命令（此时接管与原专家完全相同），否则从机器人实测状态起步（同每段开始时的初始化）。

检查（`scripts/so101_dagger_takeover_check.py`，`runs/so101_dagger_takeover_check.json`）：

| 检查 | 结果 |
|---|---|
| 有/无相机环境同种子重置（5个种子） | 目标、方块位姿、静止高度、qpos全部相同 |
| 状态保存/恢复后同一命令走一步 | qpos、qvel逐位相同 |
| 专家自驾6个无噪声训练种子，每25步取状态接管到结束（60个） | 原专家成功的52个状态接管全部完成（52/52）；原专家失败的种子4接管也失败 |
| 接管前50步与原专家实际命令之差 | 前10步与全部50步中位数均为0.0°；差异只出现在重规划（重抓时重选姿态）和搬运中参考点领先>3cm被拉回时（开头偏慢），这些情况任务仍完成 |

## 4. 训练与对照（计划，运行中）

- 数据：A第10000步驾驶400个训练种子（从3012个已存回合的种子中均匀取，`runs/so101_dagger_r1_seeds.txt`），两进程各200个，输出`runs/so101_dagger_r1_data/shard{0,1}`。
- 训练`config/so101_dagger_r1.json`：从A第10000步权重开始（新AdamW），v2全部训练帧 + DAgger样本（在均匀采样中列4次，约占20%），warmup 200，余弦5e-5→2.5e-6，5000步，micro-batch 16×4；归一化统计沿用v2（`cc2a6e1afb978a62`）。
- 对照`config/so101_dagger_r1_control.json`：同初始化、同计划与步数，只用v2数据，用于排除“多训5000步/重新退火”的作用。只有DAgger两次100种子合计完成数高于A（13/200）时才训练对照。
- 评测：第5000步（`last`）在100个验证种子上评测两次。
- 流水线`scripts/so101_dagger_r1_pipeline.sh`，`systemd-run --user`无人值守，日志`runs/so101_dagger_r1_pipeline.log`。

代码改动：`finetune_so100_real.py`新增`init_weights`；`finetune_so101_scripted.py`新增`extra_train_roots`/`extra_train_repeat`，DAgger样本直接读取自带的动作块；两个评测脚本新增`--trace`（逐步距离、抓取、夹爪命令/状态、位置）。

结论（限于本条件，仿真验证集）：

- 不改模型结构（可训练参数与A逐项相同、99,880,992个），只在A自己访问的状态上加入专家接管标签再训练5000步，完成率从约7%升到约68%；“到不了/抓不到”基本消除，完成也更快。差异远大于运行间波动（约±2）。
- 尚不能全部归因于DAgger数据：模型相对A多训练5000步且学习率重新退火。A在服务器上从第5000步到第10000步完成率未变（3/30），提示“多训练”本身不足以解释，但需对照确认。对照（`config/so101_dagger_r1_control.json`，只用v2数据，其余相同）已按规则自动开始训练。
- 剩余失败主要是抓住后未完成（17–22）与靠近未抓住（12–13），尚未分析；测试集仍未使用。
