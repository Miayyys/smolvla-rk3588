# SO101 脚本专家仿真示教数据生成

日期：2026-10-15。目的：解决[仿真策略诊断](so101-sim-policy-diagnosis.md)中暴露的两个问题：成功示教太少（5段），以及没有偏离后的纠偏数据。本轮只生成和校验数据，**尚未用于训练**，没有任何模型成绩。

## 结论

- 训练划分400个种子中专家成功350段（87.5%），共104005帧。验证30个种子成功27段/6936帧，测试50个种子成功43段/10553帧。数据量要求“训练≥200段成功示教”已满足。
- 每帧包含顶视和腕部两路320×240 RGB（JPEG q90）、6维关节state、专家干净动作标签及实际执行命令。共1.8GB。
- 独立重放8段训练示教：按记录的执行命令从同一种子重放，8/8成功，state与记录最大差≤0.0011（数据集单位，度/夹爪百分点）。
- 专家失败集中在物体距底座>0.4m的区域：该区间训练种子成功34/67，0.35m以内成功257/265。所以存储的成功示教对远处物体覆盖偏少，这是数据分布偏差，不是策略结果。

## 专家原理

实现：`qvla/evaluation/so101_scripted_expert.py`（SHA256 `62f967fe…f94e`）。

1. **读取仿真真值**：物体位姿和目标位置只供专家计算动作；记录给策略的输入只有两路图像和6维关节state。
2. **抓取姿态**：TCP坐标系z轴为手指方向，x轴为夹爪开合方向（由活动爪随关节张开时沿-x移动实测确定）。5自由度臂的接近方向只能在过底座的竖直平面内倾斜，因此按倾角候选0.35–1.3rad选择最小可达倾角；用wrist_roll让开合轴的水平投影对准最近的方块面法线。
3. **IK**：在独立MjData上做40次阻尼最小二乘迭代（姿态权重0.15），从实测关节状态出发求下一参考点的关节目标，每步关节变化限幅4°。因为每步都从实测状态重新求解，标签是反馈动作。
4. **按进度推进的阶段**：预抓取→下降→闭爪（14步）→抬起→搬运→下降→缓慢部分松爪（24步开到0.55rad）→沿手指方向慢速后退→保持。到达判定为“参考点到位且TCP误差<6mm，或连续6步停滞”。抬起后未抓住、或搬运中掉落时重试一次。
5. **噪声（DART式）**：训练种子按`seed mod 3`分配0/1/2°的OU噪声（θ=0.15），只加在预抓取、抬起、搬运三个粗移动阶段的5个臂关节上。记录的`actions`是干净专家标签，`executed`是实际执行命令。训练数据中两者平均差0.42°，最大9.85°。

## 边界与后续

- 这是读取仿真真值的脚本专家，动作风格不同于人工遥操作和作者的10段示教。
- 测试划分的43段示教只能用于离线误差；闭环评测应使用全部50个测试种子，同时单列专家也失败的7个种子。测试数据不得用于训练、统计或选模型。
- 当前训练和评测代码只支持单顶视相机。使用这份数据需要先扩展为双相机输入（`observation.images.camera1/camera2`等映射需明确记录）。之后先做单场景/少场景过拟合检查，再全量训练。
- 图像为320×240，模型processor会再缩放并padding到512（或256）。这个分辨率差异需要和部署分辨率一起考虑。
- 尚未训练、未评测任何模型，也未做量化。

## v2数据：GPUServer生成并补录特权标签（2026-10-16）

目的：为原结构基线加长训练和[目标条件化分层策略](so101-goal-conditioned-design.md)准备更大的同分布数据，并补录目标条件化训练所需的逐帧标签。训练/验证/测试仍按环境种子在过滤前固定。

### 代码改动

- `so101_scripted_expert.py`：`act()`把当步计算出的笛卡尔目标存入`last_goal`（只记录，专家不回读）；`run_episode`增加`probe(expert)`回调，在记录观测之后、执行step之前调用。
- `generate_so101_scripted_data.py`：每帧新增`tcp_pose`(7，世界系m，四元数wxyz)、`object_pose`(7)、`target_pos`(3)、`goal_pos`(3)、`goal_rot`(9，行优先3×3)、`attempt`。阶段末夹爪目标可由已存动作标签离线得到，不另存。
- `check_so101_privileged_labels.py`：同种子同噪声档与参考数据逐帧比对、FK一致性、目标合理性检查。
- Nexus源码路径改为环境变量`SO101_NEXUS_SOURCE`（服务器为`/root/so101-nexus`，提交7bdb671）。

### 实测发现

1. **仿真site位姿滞后一个物理子步。** `mj_step`先算运动学再积分，step后`site_xpos`对应上一子步（1/300s）的qpos。实测3个回合794帧：`obs['state']`与qpos差≤1.2e-7rad，数据集单位往返无损，但FK(qpos)与`_get_tcp_pose()`相差平均0.49mm、最大2.94mm；运动阶段大（carry平均1.18mm），静止阶段接近0（hold 0.009mm）。因此TCP标签改为在scratch MjData上由当前qpos做FK得到，与部署时“由state做FK求Δ”一致；不改动`u.data`，因为专家自身读取的是滞后值。
2. **BLAS多线程造成CPU超额。** 8个worker每个8线程，负载约28（8核）。限制`OMP/OPENBLAS/MKL_NUM_THREADS=1`后，同20种子试跑每回合中位耗时由10.68s降至3.26s；轨迹与多线程版本逐帧完全相同（差0）。
3. **服务器渲染。** 容器未挂载NVIDIA图形库（只有Mesa EGL，初始化失败）。Ubuntu源中的`libnvidia-gl-550`已是过渡到580的空包，apt安装会连带580驱动库，可能破坏CUDA，未采用。改为从阿里云镜像下载`libnvidia-gl-550-server_550.163.01-0ubuntu0.20.04.1`（147MB，与驱动550.163.01一致），只解压到`/root/nvidia-egl-550`，经`__EGL_VENDOR_LIBRARY_FILENAMES`和`LD_LIBRARY_PATH`使用（`env.sh`）。`GL_RENDERER`为`NVIDIA A10/PCIe/SSE2`；SO101环境含双相机渲染1.76ms/步（零动作）。实测单进程生成每帧：专家3.53ms、step(物理+渲染)3.01ms、JPEG 0.74ms。
